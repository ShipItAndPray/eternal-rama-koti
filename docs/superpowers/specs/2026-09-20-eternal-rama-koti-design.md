# Eternal Rama Koti — Design

**Date:** 2026-09-20 (revised same day after owner refinements)
**Owner:** ShipItAndPray
**Status:** approved in conversation. Sepolia first. Mainnet is a separate, later decision.

## 1. What it is

One shared Rama Koti on Ethereum. A devotee picks their language, types the name of
Rama in that script, adds their own name, and sends one transaction. The contract
verifies the typed bytes against that language's canonical form, mints one NFT to the
devotee, and advances a global count. One crore (1,00,00,000) writes completes a koti;
the count continues into the next koti forever.

Every NFT is fully on-chain: the script, the devotee's name, the writer's address,
the timestamp, and the sequence number are stored in the contract, and the image is
an SVG generated by the contract with no external references and no fonts.

Nothing can be paused, edited, upgraded, or owned. No backend, no database, no keys
after deploy. A static web page is the writing surface.

## 2. Non-goals

- No batching, relayer, gasless path, or proof of humanity. One write, one transaction.
- No mobile app, accounts, or analytics beyond the GA4 tag used on every ShipItAndPray site.
- No adding languages after deploy. The set is fixed. A new set means a new contract.

## 3. Languages

Ten scripts, each with one canonical form of "Sri Rama". Exact strings are verified
visually (rendered side by side) and confirmed by the owner before Sepolia deploy.

| id | Language | Script form |

| 0 | Telugu | శ్రీరామ |
| 1 | Hindi / Sanskrit / Marathi (Devanagari) | श्रीराम |
| 2 | Tamil | ஸ்ரீராம |
| 3 | Kannada | ಶ್ರೀರಾಮ |
| 4 | Malayalam | ശ്രീരാമ |
| 5 | Bengali | শ্রীরাম |
| 6 | Gujarati | શ્રીરામ |

| 8 | Punjabi (Gurmukhi) | ਸ਼੍ਰੀਰਾਮ |

The contract maps `keccak256(bytes(form))` to language id. Any other bytes revert.

## 4. Contract: `EternalRamaKoti.sol`

Solidity ^0.8.24, Foundry. Runtime dependencies: none. A vendored MIT Base64
encoder lives in `src/lib/`.

### Constants

`KOTI = 10_000_000`. `MAX_NAME_BYTES = 31`.

### State

| Name | Type | Meaning |
|---|---|---|
| `count` | `uint256` | tokens minted, all time; also the next token id minus one |
| `written` | `mapping(address => uint256)` | writes by address; doubles as `balanceOf` |
| `writers` | `uint256` | distinct addresses with at least one write |
| `entries` | `mapping(uint256 => Entry)` | per-token data |

```
struct Entry {
    address writer;    // 20 bytes
    uint8   lang;      // 1
    uint40  timestamp; // 5
    uint8   nameLen;   // 1   -> slot 1
    bytes32 name;      //     -> slot 2, UTF-8, left-aligned
}
```

### Writing

`write(string calldata rama, string calldata name)`:

1. `lang = langOf[keccak256(bytes(rama))]`; revert `UnknownForm()` if unset. Ids are
   stored plus one so id 0 is distinguishable from unset.
2. Validate `name`: 1 to 31 bytes; English only. Every byte must be `A-Z`, `a-z`,
   space, `.` or `-`. Revert `BadName()` otherwise. This makes the name safe to embed
   in JSON and SVG without escaping, and guarantees it renders on every viewer.
3. `count += 1; id = count`.
4. If `written[msg.sender] == 0` then `writers += 1`. `written[msg.sender] += 1`.
5. Store `entries[id]`.
6. Emit `Transfer(address(0), msg.sender, id)` and `Written(address indexed writer,
   uint256 indexed id, uint8 lang)`.
7. If `id % KOTI == 0` emit `KotiComplete(uint256 indexed koti)`.

`receive()` and `fallback()` revert. No other state-changing function exists.

### Views

`count()`, `writers()`, `written(address)`, `kotisCompleted()`, `entry(uint256)`
returning the decoded entry with the name as a string and the language form,
`forms(uint8)` returning the canonical string for a language id, `LANG_COUNT()`.

### ERC-721 surface (soulbound)

- `name()` "Eternal Rama Koti", `symbol()` "RAMA".
- `ownerOf(id)` returns `entries[id].writer`; reverts for id 0 or id > count.
- `balanceOf(a)` returns `written[a]`.
- `tokenURI(id)` returns `data:application/json;base64,...`.
- `transferFrom`, both `safeTransferFrom`, `approve`, `setApprovalForAll` revert
  `Soulbound()`. `getApproved` returns zero, `isApprovedForAll` returns false.
- `locked(id)` (ERC-5192) returns true for any minted id.
- `supportsInterface` for ERC-165, ERC-721, ERC-721Metadata, ERC-5192.
- `contractURI()` returns on-chain JSON with collection name, description, and a
  small emblem SVG.

Soulbound is the default because a written name is an offering, not a collectible.
The owner can flip this before mainnet; it is a one-line change and a test change.

### Metadata

```
{
  "name": "శ్రీరామ #12,345",
  "description": "One name of Rama, written by <name> on Ethereum. Entry 12,345 of the Eternal Rama Koti.",
  "image": "data:image/svg+xml;base64,...",
  "attributes": [
    {"trait_type":"Language","value":"Telugu"},
    {"trait_type":"Written by","value":"<name>"},
    {"trait_type":"Index","display_type":"number","value":12345},
    {"trait_type":"Koti","display_type":"number","value":1},

```

### Image

Cream card, saffron rule, deep red ink. Centered: the Rama form as a glyph outline
`<path>`, scaled to width. Below it, in a generic serif `<text>`: the devotee's name,
then `#12,345 of 1,00,00,000` in Indian digit grouping, then `Koti 2` only when
`id > KOTI`. No fonts, no external references, under 10 KB per token.

Glyph outlines are produced once, offline, by shaping each canonical form with
HarfBuzz through Noto Serif (or Noto Sans where Serif is unavailable) for that script,
extracting outlines with fontTools, and rounding to a 1000-unit grid. The build
script, font files' versions, and resulting paths are committed. The ten paths are
stored on-chain in data contracts (raw bytes as runtime code, read with
`extcodecopy`) whose addresses are immutables on the main contract. The main contract
stays under the 24 KB size limit.

### Gas

Target for `write` after an address's first write: under 110,000 gas. First write
from an address: under 130,000. `forge snapshot` committed.

## 5. Web app: `web/`

Static. `index.html`, `app.js`, `style.css`, `config.js`, `glyphs.js` (the same ten
paths, for local preview). `viem` from jsDelivr as an ES module. No build step.
Hosted on GitHub Pages.

### Reads, no wallet

- `count`, `writers`, `kotisCompleted` via `eth_call` on keyless RPCs. Sepolia:
  PublicNode Sepolia primary, with two fallbacks. Mainnet list ready in config.
- Recent entries: last 24 `Written` events via Blockscout's keyless API for the
  active chain, each rendered by fetching `tokenURI` and inlining the SVG.
- Live cost before signing: `eth_gasPrice` × 110,000 × ETH/USD from CoinGecko's
  keyless endpoint. If CoinGecko fails, show gwei only.

### Writing flow

1. Pick a language. The canonical form is shown large.
2. Type it. Romanized typing (`srirama`) reveals the script progressively by
   syllable; native keyboard input is accepted when it matches exactly. Paste, drop,
   and autofill are blocked. Client-side check: bytes equal the canonical form.
3. Type your name. Same validation as the contract, with a live byte counter.
4. Connect a wallet via EIP-6963 injected discovery. Request a chain switch if needed.
5. Offer: one transaction calling `write(rama, name)`. Show live cost first.
6. On confirmation: render the new token's SVG straight from `tokenURI`, show
   "Written. You have written N.", and reset for the next one.
7. On connect, show the devotee's own count and their recent tokens.

Mobile: works in wallet in-app browsers. A MetaMask deep-link button is shown when
no injected wallet is found.

### Design

Devotional and dignified: cream, saffron, deep red, generous whitespace. Above the
fold: the live count with progress toward one crore, the one-line explanation, the
per-write cost, and the language picker. Follow the frontend-design skill.

## 6. Deployment

1. `forge test` green, snapshot committed, all ten forms visually verified by owner.
2. Generate a deployer key into `.env` (gitignored). Owner funds it with Sepolia ETH.
3. Deploy to Sepolia. Verify on Sourcify (keyless). Publish web app pointed at Sepolia.
4. Owner writes real entries on Sepolia from their own wallet.
5. Mainnet is a separate decision made after Sepolia. Not part of this build.
6. Repo `ShipItAndPray/eternal-rama-koti`, MIT for code, glyph paths under the
   fonts' SIL OFL. README with live link, contract address, how to write by hand
   from any wallet, gas cost, and the language table. GitHub Pages enabled.

## 7. Testing

Foundry: every language form mints with the right `lang`; a near-miss form reverts;
each name validation rule reverts on its own (empty, 32 bytes, each forbidden char,
a control byte) and a Telugu-script name of 30 bytes passes; same address repeat
writes increment `written` and leave `writers` unchanged; ids are sequential;
`ownerOf` and `balanceOf` agree with entries; `KotiComplete` at exactly 10,000,000
and 20,000,000 via `vm.store` on the `count` slot; `tokenURI` decodes to JSON that a
strict parser accepts and whose image decodes to an SVG containing the name and the
grouped index; `tokenURI` of an unminted id reverts; all transfer and approval paths
revert `Soulbound()`; `supportsInterface` for the four ids and false for a random one;
`receive` and `fallback` revert; gas snapshot for first and repeat writes.

Glyph build: a script check that each committed path, rendered, matches a PNG
reference generated from the font, reviewed by eye once in a side-by-side collage.

Web app: manual checklist on Sepolia in a real browser, including a Telugu name.

## 8. Costs and risks, stated honestly

- Sepolia costs nothing. Mainnet, if chosen later, at 0.063 gwei and ETH $2,624
  (measured 2026-09-20): deploy with ten glyph contracts ≈ $3; one write ≈ $0.02
  paid by the writer; one crore of writes ≈ $200,000 collectively. Gas spikes raise
  it linearly. The page shows live cost before every signature.
- Bots can write at their own expense. The count measures writes, not intent.
- The devotee's name is English-only by rule, so it renders on every viewer with a
  generic serif. The Rama form is an outline and never depends on fonts.
- Public RPCs can rate-limit. Config lists three per chain.
